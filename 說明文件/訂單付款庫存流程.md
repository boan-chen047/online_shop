# 訂單／付款／庫存 狀態機規格

> 對應 migration：`supabase/migrations/202609190001_order_reserve_state_machine.sql`
> 相關 Edge Function：`ecpay-create`、`ecpay-callback`

本文件說明「加入購物車 → 下單 → 綠界付款 → 出貨／逾時取消」的完整狀態流轉與庫存規則。

## 一、核心設計：預留式庫存（reserve）

`inventory` 兩個數字：

- `quantity`：**實體在庫數**（倉庫實際有幾個）
- `reserved_quantity`：**被未付款訂單佔住的數量**
- **可售量 = `quantity − reserved_quantity`**（資料庫另有 `reserved_quantity <= quantity` 約束）

庫存在三個時點變動：

| 時點 | quantity | reserved_quantity |
|---|---|---|
| 下單（建立未付款訂單） | 不變 | **+ 數量**（預留） |
| 付款成功 | **− 數量** | − 數量（結清預留） |
| 三天逾時取消 | 不變 | **− 數量**（釋放預留） |

## 二、狀態值

**付款狀態 `payment_status`**：`unpaid` 未付 / `paid` 已付 / `failed` 付款失敗 / `refunded` 已退款 / `expired` 逾時未付

**出貨狀態 `order_status`**：`created` 已成立 / `shipping` 出貨中 / `received` 已收貨 / `cancelled` 已取消 / `out_of_stock` 已付款但缺貨待退款

## 三、流程

```
加入購物車（cart_items，與訂單無關，可跨登入保留）
        │  按下結帳
        ▼
create_order_from_cart()
  ├─ 依 product_id 排序鎖住庫存列（for update）→ 保證「先到伺服器的訂單先贏」
  ├─ 可售量不足 → 拋出 'OUT_OF_STOCK:商品名'，整筆訂單失敗（不建單、不預留）
  └─ 可售 → 建立 unpaid / created 訂單、reserved_quantity += 數量、清空已結帳購物車
        │  前往綠界收銀台（ecpay-create，ExpireDate=3 對齊三天）
        ▼
綠界付款結果（ecpay-callback，server-to-server）
  ├─ RtnCode=1 → 呼叫 mark_order_paid()
  │     ├─ 已 paid：回 'already_paid'（幂等，避免綠界重送重複結清）
  │     ├─ unpaid/failed：quantity −= 數量、reserved −= 數量 → paid
  │     └─ expired（遲到付款）：重新確認庫存
  │           ├─ 有貨：quantity −= 數量 → paid / created（訂單復活）
  │           └─ 沒貨：paid / out_of_stock（收款成立、待退款）
  └─ RtnCode≠1（付款失敗）：不動作，訂單維持 unpaid，可於三天內重試付款
        │
        ▼（下單滿 3 天 2 小時仍未付款）
expire_unpaid_orders()（pg_cron 每 10 分鐘）
  └─ reserved −= 數量（釋放）、訂單標記 expired / cancelled（紀錄保留，不刪除）
```

## 四、關鍵決策紀錄

1. **下單即預留、非付款才扣**：要支援「先搶先贏、後到擋掉」就必須在下單當下佔住庫存。
2. **先到先贏用資料庫列鎖**：`for update` 讓先取得鎖的交易先成立，後者重算可售量後失敗；多商品訂單一律依 `product_id` 排序上鎖以避免死結。
3. **逾時取消不刪除訂單**：金流／訂單紀錄一律「軟取消」（標 `expired`/`cancelled`）永久保留，供對帳、發票、退款、客訴、遲到付款認帳使用。硬刪為禁止事項。
4. **綠界端到期靠 ExpireDate**：讓綠界自己的繳費期限對齊三天，而非事後呼叫 API 作廢（AIO 對未付款代碼無可靠即時作廢）。信用卡為即時付款無殘留。
5. **遲到付款一律認帳**：逾時取消後才收到的付款，有貨復活、沒貨標記 `out_of_stock`——確保「收了錢」永遠有對應處理，不會發生收款卻查無此單。
6. **釋放時間比綠界繳費期限晚 2 小時**：綠界 `ExpireDate` = 3 天、我方釋放預留 = 下單後 3 天 2 小時。綠界一定先關閉繳費，因此「釋放預留後綠界的遲到付款才到」→ `out_of_stock` 在實務上不會發生（信用卡為即時付款更不可能）。`out_of_stock` 狀態僅作為極端情況的保險絲，暫不需要主動退款流程。
